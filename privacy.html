PhishGuard data handling

PhishGuard performs its ordinary page and message checks in the browser. Page inspection is local by default. The extension does not send the user's page text, typed text, keystrokes, passwords, payment-card values, one-time codes, cookies, or form-field values to the PhishGuard service.

What the live page monitor observes

On supported web pages, the extension inspects the rendered document and permitted frames. It builds a bounded inventory of DOM element counts, selected element attributes, links and destination hosts, form methods and action hosts, field types (not field values), script hosts, iframe metadata, resource hosts, open shadow roots, and security-relevant attributes. It also counts interaction categories such as clicks, focus, input/change events, keyboard interaction, copy/paste, form submission/reset, scrolling, navigation, and DOM changes.

A small recent-event list is held in memory for the current page and contains event category, element type, and relevant destination/form-action host metadata. It does not record actual keys, clipboard contents, typed values, or the content of form fields. Page inventories and interaction metadata are kept in the extension's active-session memory and are not part of a community report.

Coverage limits

Chrome and Firefox restrict extension access to browser-internal pages, some protected pages, built-in PDF viewers, and the browser's own store pages. Closed shadow roots are not exposed to ordinary extensions. Cross-origin frames are inspected only when the browser permits the extension to inject its content script. Inventory detail is bounded to protect page performance; the interface reports when detail caps are reached. PhishGuard therefore cannot promise visibility into every browser surface or every element.

Optional hosted Playwright inspection

The publisher may configure an HTTPS Playwright service for an additional public-URL scan. This scan runs when the user enables optional automatic remote link checks or explicitly selects a link to inspect. The extension sends the destination origin and path, with fragments and recognized sensitive query parameters removed. Other routing parameters may remain; URL paths and parameters may still contain personal information. The service loads the destination in a new, unsigned-in, isolated Chromium context; it does not reuse the user's browser profile, cookies, authorization headers, or logged-in session. The service refuses non-GET/HEAD page requests, downloads, and pop-up windows, and it does not execute downloaded files.

The hosted service receives the submitted URL and makes network requests to the public destination and its resources. The service operator and hosting provider may process request metadata such as the caller's IP address, requested host/path, timestamps, and operational logs. Configure the service only on infrastructure you control or trust, publish its retention policy, use HTTPS, and apply edge-level abuse protection. No hosted service is configured in an unconfigured publisher build; end users do not install Node.js or run a local companion.

Threat lists, icons, and reports

The extension downloads public threat-list files and may request the current site's icon for local brand comparison. Those requests disclose normal network metadata to the relevant hosting providers.

Community reporting is off by default and requires an HTTPS relay URL that you configure and the user explicitly enables. A report may include the domain, verdict, reason codes, compact numeric risk signals, matched brand names, extension version, and event time. Reports are not designed to include raw page text, typed content, cookies, full URL paths, or query strings. The relay operator determines its own retention and processing practices.

Local text model

The optional English text classifier runs on-device using the runtime included in the extension. Its model weights, vocabulary and JavaScript/WebAssembly runtime are included in the extension package. Text classification requires no model-host network request; page text is processed locally. Chrome may separately download Gemini Nano after the user enables that optional capability. Model failure or device limits leave the lightweight checks active.

Controls

Settings, local history, feedback, and the live page monitor remain in browser memory/storage unless a feature explicitly described above transmits data. Users can disable community reporting in Settings, clear local history, and disable the extension at any time.
